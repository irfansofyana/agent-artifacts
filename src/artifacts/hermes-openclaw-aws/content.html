Running Hermes and OpenClaw on AWS

AWS now ships first-party material for both agents: a campaign page, a Lightsail quick start, one-click CloudFormation samples, Marketplace listings and four Builder Center write-ups. The community layer is thin, and only one Terraform module looks maintained.

The 3 deployable samples worth cloning

aws-samples/sample-OpenClaw-on-AWS-with-Bedrock

AWS sampleMIT-0418★

One CloudFormation stack that stands up OpenClaw on a Graviton instance with Bedrock for model access, SSM Session Manager instead of open SSH, VPC endpoints and CloudTrail. The README claims about 8 minutes to deploy and prices it from roughly $30/month. Messaging plugins arrive pre-installed. Launch buttons cover us-west-2, us-east-1, eu-west-1 and ap-northeast-1.

  • Bedrock model access is handled by the stack, so no API keys live on the instance.
  • Access is through SSM, so no inbound ports and no SSH key.
  • Caveat: the one-click template sits in a single S3 bucket, so any other region means uploading the template yourself.

aws-samples/sample-host-hermesagent-on-amazon-bedrock-agentcore

AWS sampleMIT-045★

The most architecturally interesting option for Hermes: per-user Firecracker microVMs on AgentCore Runtime, 9 CDK stacks, API Gateway plus a router Lambda for inbound webhooks, and an ECS Fargate gateway for channels that need long-lived connections. State is S3-backed so memory and sessions survive the microVM.

  • The integration is a monkey-patch that swaps anthropic.Anthropic for anthropic.AnthropicBedrock, so all inference goes through Bedrock with SigV4 and IAM while upstream Hermes source stays unmodified.
  • Channels: Telegram, Slack, Discord and Feishu over webhook; WeChat through the Fargate gateway.
  • Caveat: region-gated, see the Jakarta section.

JiaDe-Wu/sample-hermes-agent-on-aws-with-bedrock

MIT19★

The sample the Hermes docs themselves link to: CloudFormation creates the VPC, IAM role, EC2 instance and Bedrock configuration in one click. Its native Bedrock provider work has been merged upstream, so the deployment installs from the official PyPI release rather than a fork. Shortest path from zero to a working Hermes on EC2.

There is also aws-samples/sample-hermes-agents-on-agentcore, younger and thinner, useful if you want more than one Hermes agent inside the same AgentCore account.

Both agents speak Bedrock natively

This is what makes the whole AWS story work: it removes API keys from the picture. Auth is the AWS SDK credential chain, so an instance role is enough.

OpenClaw ships a Bedrock Converse streaming provider plus a separate Bedrock Mantle provider for the OpenAI-compatible endpoint that serves open models.

# OpenClaw: provider metadata
# provider: amazon-bedrock
# api:      bedrock-converse-stream
# auth:     aws-sdk  (env vars, shared config, or instance role)

# On EC2 the instance role is invisible to env-marker detection,
# so discovery has to be turned on explicitly:
openclaw config set plugins.entries.amazon-bedrock.config.discovery.enabled true
openclaw config set plugins.entries.amazon-bedrock.config.discovery.region ap-southeast-3
openclaw models list

Discovery calls bedrock:ListFoundationModels and bedrock:ListInferenceProfiles and caches for an hour. Bare foundation-model IDs are only listed when Bedrock reports on-demand support; models that are profile-only appear as their us. or global. profiles instead, since those profiles carry different data-residency behaviour. You can still add a hidden model by hand under models.providers["amazon-bedrock"].models.

Hermes Agent routes each model family through the API that serves it best instead of forcing everything down one path.

# Hermes Agent: Bedrock provider
cd ~/.hermes/hermes-agent && python -c "import pm; pm.sync_venv(['bedrock'], explicit=True)"
hermes model        # More providers... -> AWS Bedrock -> region -> model

# config.yaml afterwards
# model:
#   default: us.anthropic.claude-sonnet-4-6
#   provider: bedrock
# bedrock:
#   region: ap-southeast-3

OpenClaw Enterprise is the scale path

openclaw/openclaw-enterprise is MIT-licensed, actively developed, and ships EKS deployment guides for its Helm installation, including private-only cluster API access and cleanup. That is the only route to per-user isolation that is not hand-rolled.

Jakarta reality check

ap-southeast-3 covers EC2 and Lightsail, not AgentCore

Checked against AWS regional availability data on 18 November 2026: Amazon Bedrock and Amazon Lightsail both report available in ap-southeast-3. Amazon Bedrock AgentCore reports planned, not available.

So the EC2 and Lightsail paths run in Jakarta today with Bedrock as the model back end. The AgentCore-based Hermes sample needs a neighbouring region until AgentCore lands, which makes it an explicit cross-region data-processing decision rather than a default.

One more Jakarta-shaped detail: the CloudFormation launch buttons in both aws-samples repositories point at fixed regions and a single template bucket. For ap-southeast-3 you re-host the template in your own bucket, launch from there, and verify which models are actually available in-region before picking default model IDs.

What I would actually do

  1. Jakarta, EC2, Bedrock. Launch a Graviton instance from the aws-samples CloudFormation sample, re-hosted for ap-southeast-3. IAM role for Bedrock, SSM for access, no inbound ports. Shortest path that satisfies a Jakarta-only constraint today.
  2. Keep the AgentCore sample on the shelf. It is the better long-term architecture for per-user isolation, but it is not deployable in Jakarta yet, and moving the CDK stacks to a neighbouring region is a data-residency decision, not a config change.
  3. Skip EKS unless multi-tenancy is the actual requirement. One agent per person on its own instance is cheaper and easier to reason about than a cluster with per-user cells, and OpenClaw's own security guidance says a shared gateway is not a trust boundary.
  4. Borrow the Terraform module only for the AWS-native edge. infrahouse/terraform-aws-openclaw is worth reading for the ALB plus Cognito pattern, but a personal gateway behind SSM does not need an ALB.
