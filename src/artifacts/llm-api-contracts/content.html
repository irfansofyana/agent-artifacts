Field guide · checked 30 September 2026. A contract is the request/response shape, not a model capability. “OpenAI-compatible” means a particular API surface is translated; it does not promise identical tools, state, streaming, model availability, or retention. These are illustrative schema slices, not captured live responses: IDs and text are placeholders, and omitted optional fields vary by model. Follow the linked first-party references before shipping.

01 · The mental model

Choose across four axes: input unit (prompt, role-message, content block, or item), output unit (text, choice, block, candidate, or typed step), state owner (your application or provider), and tool owner (your code or server-side tool). A compatible client is only the beginning of compatibility.

03 · Six request/response shapes

The same task (“say hello”) exposes the structural differences. Examples below omit authentication headers and unrelated optional fields. The response fragments show where application code reads the answer; do not treat them as exhaustive JSON Schemas.

A · Legacy text completion

POST https://api.openai.com/v1/completions. One freeform prompt enters; a choice's text comes out. Anthropic's separate legacy /v1/complete has its own format; these are not interchangeable.

// request
{"model":"<completion-capable-model>","prompt":"Say hello."}
// response fragment
{"choices":[{"text":"Hello!","finish_reason":"stop"}]}

Use only for a supported legacy/prefix-suffix workflow, not as a new agent default. OpenAI legacy guide · Anthropic legacy reference.

B · OpenAI Chat Completions

POST https://api.openai.com/v1/chat/completions. Role messages enter; choices[0].message exits. Your application supplies the relevant prior turns on the next request.

// request
{"model":"<chat-capable-model>","messages":[{"role":"user","content":"Say hello."}]}
// response fragment
{"choices":[{"message":{"role":"assistant","content":"Hello!"},"finish_reason":"stop"}]}

OpenAI reference. Google, OpenRouter, and Bedrock document compatible Chat endpoints, but inspect model support and optional parameter handling before switching base URLs.

C · Anthropic Messages

POST https://api.anthropic.com/v1/messages. The system instruction is top-level, not a role in messages. Content is an array of typed blocks; max_tokens is required.

// request
{"model":"<claude-model>","max_tokens":128,"system":"Be concise.",
 "messages":[{"role":"user","content":"Say hello."}]}
// response fragment
{"role":"assistant","content":[{"type":"text","text":"Hello!"}],
 "stop_reason":"end_turn","usage":{"input_tokens":12,"output_tokens":4}}

Stateless multi-turn: pass earlier turns again. The numeric usage shown is illustrative. Anthropic reference.

D · OpenAI Responses

POST https://api.openai.com/v1/responses. input may be a string or items; output is an array of typed items. A reasoning item or tool call may appear before an assistant message. The SDK's output_text is a convenience, not the wire response's universal first field.

// request
{"model":"<responses-capable-model>","input":"Say hello.","store":false}
// response fragment
{"id":"resp_example","output":[{"type":"message","role":"assistant",
 "content":[{"type":"output_text","text":"Hello!"}]}]}

OpenAI recommends Responses for new projects. If using provider-managed conversation state, follow its store/previous_response_id policy explicitly; stateless callers must preserve required context, including reasoning items as applicable. Migration and state guide.

E · Google Gemini generateContent

POST https://generativelanguage.googleapis.com/v1beta/models/{model}:generateContent. The URL selects the model; request contents[] contains role-and-part objects; systemInstruction, tools, generationConfig, and safetySettings are separate fields. Response candidates[] contain content.parts[], with finishReason; usage lives in usageMetadata. For a multi-turn stateless call, send the history in contents.

// request body; model is in URL
{"systemInstruction":{"parts":[{"text":"Be concise."}]},
 "contents":[{"role":"user","parts":[{"text":"Say hello."}]}]}
// response fragment
{"candidates":[{"content":{"role":"model","parts":[{"text":"Hello!"}]},
 "finishReason":"STOP"}],"usageMetadata":{"promptTokenCount":12,
 "candidatesTokenCount":4}}

Important update: Google now calls generateContent legacy-but-supported and recommends its native Interactions API for new Gemini projects. Do not mistake Gemini's OpenAI-compatible Chat endpoint for its native schema. generateContent reference · Interactions overview.

F · Google Gemini Interactions

POST https://generativelanguage.googleapis.com/v1beta/interactions. A turn becomes an Interaction resource with typed steps[], such as model_output and tool steps. Optional previous_interaction_id continues server-side history; store:false opts out of storage. Unlike a transcript alone, most request settings (tools, system_instruction, generation_config) need to be re-specified on subsequent interactions.

// request
{"model":"gemini-3.8-flash","input":"Say hello.","store":false}
// response fragment
{"id":"interaction_example","object":"interaction","status":"completed",
 "steps":[{"type":"model_output","content":[{"type":"text","text":"Hello!"}]}]}

Google states Interactions became GA in June 2026 and recommends it for new projects. Check retention before enabling stored state. Overview · REST schema.

04 · Bedrock is a platform, not one format

Converse: AWS-normalized chat for supported models. POST /model/{modelId}/converse; messages, system, inferenceConfig, toolConfig enter; output.message, stopReason, usage exit. Start here for AWS-native multi-model chat. InvokeModel: POST /model/{modelId}/invoke passes a model-specific body; use for native capabilities and non-chat tasks such as embeddings/images. Compatibility APIs: OpenAI Chat/Responses and Anthropic Messages use different Bedrock base URLs and support sets. Match the model card, Region, endpoint, and auth scheme—not just the API family's name.

// Converse request fragment
{"messages":[{"role":"user","content":[{"text":"Say hello."}]}],
 "inferenceConfig":{"maxTokens":128}}
// Converse response fragment
{"output":{"message":{"role":"assistant","content":[{"text":"Hello!"}]}},
 "stopReason":"end_turn","usage":{"inputTokens":12,"outputTokens":4}}

Bedrock recommends bedrock-runtime for new compatible applications when the model and features are available; bedrock-mantle remains a compatibility route for capabilities absent on runtime. Bedrock Responses storage is on by default; AWS documents a 30-day stored-response retention window and store:false to disable it. Runtime Responses lacks Mantle's background execution and server-side tools. Converse guide · InvokeModel reference · Responses endpoints and state · Messages endpoints.

06 · What breaks at the boundary

  • State and privacy: distinguish resending history from referencing stored IDs. Set storage deliberately. OpenRouter Responses rejects store:true and non-null previous_response_id; Bedrock Responses stores by default; Gemini Interactions stores by default. OpenRouter · Bedrock · Google.
  • Streaming: parse the provider's event grammar, not raw text chunks. OpenAI Responses emits typed events such as response.output_text.delta; Anthropic emits content_block_delta and partial JSON tool arguments; Bedrock has ConverseStream. OpenAI · Anthropic · AWS.
  • Stopping and errors: finish_reason, stop_reason, stopReason, finishReason, and status are not interchangeable. Handle tool handoffs, truncation, refusals/safety filtering, and incomplete output before reading text.
  • Feature parity: a successful text call does not establish that function calling, JSON constraints, multimodal parts, reasoning carryover, caching, model listing, or built-in tools work through a compatible endpoint. Probe each required feature with its intended model and Region. Bedrock matrix · OpenRouter transformations.

07 · Pick the endpoint

  1. OpenAI-first new agent: Responses. For a simple established multi-provider chat adapter, Chat Completions is a reasonable narrow common denominator. Source.
  2. Claude-first: native Anthropic Messages. Source.
  3. AWS-native multi-model chat: Bedrock Converse; choose InvokeModel for a model-native/non-chat need. Existing OpenAI/Anthropic clients can instead use Bedrock-compatible APIs after model/endpoint verification. Source.
  4. OpenRouter routing: Chat Completions for the conventional adapter; Responses only when its stateless restriction is acceptable. Source.
  5. New Gemini-native app: Interactions; retain generateContent for existing integrations or when that API's documented feature path is the fit. Google's OpenAI-compatible Chat endpoint is for migration, not the native Gemini schema. Source · Compatibility.

Implementation principle: keep an internal typed transcript (turns, content parts, tool call IDs/results, finish states, usage) and one adapter per contract. Preserve unknown provider-specific fields separately rather than pretending everything collapses to {role, content}. Test both directions of every adapter, plus a live capability probe when credentials are available.
