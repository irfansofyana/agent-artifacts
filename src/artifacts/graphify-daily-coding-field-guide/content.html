A map for your coding agent.

Graphify turns a repository into a local, queryable graph of symbols and relationships. The useful habit is not “graph everything.” It is: query the map for system-level questions, then verify the answer in source before editing.

Kai’s take

Use Graphify as a navigation layer—not an oracle, not a replacement for grep, LSP, tests, or reading the code you will change.

01 · Mental model

From files to relationships, in seven moves.

For code-only repositories, the core path is deterministic and local. Mixed corpora add an LLM semantic pass for docs, PDFs, and images.

01DetectWalk supported files; honor gitignore and .graphifyignore.
02ParseTree-sitter reads ASTs: functions, classes, imports, calls.
03ResolveConnect symbols across files and tag confidence.
04BuildMerge nodes and edges into a NetworkX graph.
05ClusterLeiden when installed; otherwise Louvain groups dense regions.
06AnalyzeFind hubs, bridges, surprising links, questions.
07ExportWrite graph.json, graph.html, and GRAPH_REPORT.md.
What is stored
UserServicenode · class · src/user.ts:L18
callsedge · EXTRACTED · confidence 1.0
saveUser()node · function · src/db.ts:L44

A node is a code or content concept. An edge says how two concepts relate and where that relationship came from.

Critical distinction

Structural ≠ semantic

Code: parsed locally with tree-sitter; no LLM is needed for the normal code path.

Docs / PDFs / images: semantic extraction uses the host assistant or a configured model backend. That content may leave the machine, depending on your setup.

Audio / video: transcription can run locally with faster-whisper.

02 · Why agents care

A graph answers a different class of question.

Text search finds matching strings. A graph traverses relationships. Coding agents need both.

A

Find the neighborhood

“What touches authentication?” can return routes, services, persistence, config, and tests—even when they use different words.

B

Trace a path

“How does checkout reach the ledger?” becomes a shortest-path question rather than a sequence of guesses and greps.

C

Scope context

The agent receives a small subgraph instead of stuffing the whole repository into its context window.

D

Keep provenance visible

EXTRACTED means explicit in source. INFERRED means resolution or deduction. AMBIGUOUS means inspect manually.

03 · Setup

Install once. Register per agent.

The PyPI package is graphifyy (double “y”); the command is graphify. Prefer uv tool for an isolated install.

Pi coding agent

Graphify ships a Pi skill. Use the verified global install: Graphify’s current project-scoped Pi path does not match Pi’s documented project skill directories.

uv tool install graphifyy graphify install --platform pi
# enable Pi skill commands, then invoke from the repository root /skill:graphify . # after the graph exists, direct CLI queries are unambiguous graphify query "trace request authentication to persistence"
Integration mechanism: ~/.pi/agent/skills/graphify/. Pi registers skills as /skill:name, so the verified command is /skill:graphify—not /graphify. Natural-language skill matching also works.

Cursor

Cursor gets an always-applied rule at .cursor/rules/graphify.mdc. This is instruction-based, not a Graphify slash command or runtime hook.

uv tool install graphifyy graphify cursor install # equivalent generic form: graphify install --platform cursor # build explicitly from a terminal graphify extract . --code-only
# then ask Cursor Agent conversationally: "Use graphify first. Show the blast radius of changing TokenService, then verify the relevant source files before editing." # or ask it to run: graphify query "blast radius of TokenService"
Integration mechanism: alwaysApply: true Cursor rule. Graphify does not install a verified Cursor /graphify command; use natural language or direct CLI commands.

Claude Code

Claude Code receives a skill, project instructions, and PreToolUse hooks that nudge search/file reads toward the graph.

uv tool install graphifyy graphify install # recommended for one repository graphify install --project # optional stronger first-read guard graphify install --project --strict
/graphify . /graphify query "what connects the API layer to billing?" /graphify path "CheckoutService" "LedgerWriter" /graphify explain "RetryPolicy"
Integration mechanism: CLAUDE.md guidance plus PreToolUse hooks. Strict mode blocks the first raw source read in a session and redirects once—then falls back to a nudge.

Standalone CLI

You can build and query without any coding-agent integration. Use this in scripts, CI, or before deciding whether to adopt the skill.

uv tool install graphifyy graphify extract . --code-only graphify query "where is authorization enforced?" graphify path "ApiRoute" "PermissionCheck" graphify explain "PermissionCheck"
# incremental maintenance graphify update . # update automatically after commits graphify hook install # browser visualization xdg-open graphify-out/graph.html
Safer first trial: use --code-only. It stays local and skips semantic processing of docs, PDFs, and images.

04 · Daily use

Six jobs where the map earns its keep.

Each workflow ends with source verification. That is the line between useful code intelligence and confidently editing from stale metadata.

New repository · 15–30 min

Architecture onboarding

  1. Build the code-only graph.
  2. Open GRAPH_REPORT.md for the broad map.
  3. Query each major subsystem.
  4. Read 2–3 hub files in source.
graphify query "entry points, core domain, persistence, and external integrations"
Deliverable: a one-page system sketch plus five files worth reading first.
Before implementation

Change-impact analysis

  1. Explain the target symbol.
  2. Inspect incoming and outgoing relationships.
  3. Trace paths to public APIs and storage.
  4. Verify callers with LSP/grep before touching code.
graphify query "blast radius if RefreshTokenStore changes; include callers, tests, config, and persistence"
Deliverable: owned files, risky edges, test plan, and rollback point.
Bug investigation

Trace a failing flow

  1. Name the observed entry and suspected sink.
  2. Use path to expose bridge nodes.
  3. Inspect logs/tests around that path.
  4. Ask the agent for competing hypotheses.
graphify path "POST /checkout" "LedgerWriter" # then: verify every hop in source and list missing runtime evidence
Deliverable: a bounded hypothesis tree—not a speculative fix.
Refactor planning

Cut a subsystem safely

  1. Find the community containing the target.
  2. List cross-community edges.
  3. Separate interface edges from accidental coupling.
  4. Plan migration slices at graph boundaries.
graphify query "all cross-community dependencies of BillingService; classify inbound vs outbound"
Deliverable: migration order and seams worth introducing.
Pull request review

Review beyond the diff

  1. Update the graph after checkout.
  2. Map changed symbols to their neighborhoods.
  3. Check callers and downstream state.
  4. Compare graph risk with test coverage.
graphify prs 42 # or ask the agent: "Map changed symbols to affected communities and untested callers."
Deliverable: review questions the textual diff alone would not reveal.
End of coding session

Keep the map trustworthy

  1. Run tests and normal quality gates.
  2. Update Graphify after code changes.
  3. Check that removed files/symbols disappeared.
  4. Commit shared output only if the team agreed.
graphify update . graphify query "what changed around the symbols edited in this branch?"
Deliverable: a current graph for tomorrow’s agent session.
01OrientBroad graph query; identify subsystem and hubs.
02NarrowExplain or path query; select a small neighborhood.
03VerifyRead source, use LSP/grep, inspect tests and runtime evidence.
04ChangeGive the agent a bounded task and acceptance criteria.
05RefreshTest, then update the graph so future context is not stale.
05 · Judgment

Do not query a graph for everything.

The fastest tool depends on the question. Graphify is strongest when relationships matter across files or subsystems.

QuestionBest first toolWhyGraphify?
“Where is this exact error string?”grep / ripgrepExact lexical lookup is direct and cheap.No
“Who calls this function?”LSP referencesCompiler-aware references are usually more precise.Maybe, for cross-language context
“How does auth reach the database?”Graphify path/queryRelationship traversal across files is the point.Yes
“What breaks if this service changes?”Graphify → LSP → testsMap blast radius, verify references, prove behavior.Yes
“Why did this request fail in production?”logs / traces / metricsA static graph has no runtime truth.Supporting context only
“Is this implementation correct?”tests + source reviewConnectivity is not correctness.Not by itself
Failure modes to remember
  • Staleness: a graph built before the latest refactor can mislead. Run graphify update .
  • Lexical query seeding: graphify query is lexical scoring plus graph traversal—not embedding search or semantic question answering. Include exact symbol, file, or subsystem names when broad prose returns noise.
  • Inference risk: treat INFERRED and AMBIGUOUS edges as hypotheses; follow provenance into source.
  • Static blind spots: reflection, dependency injection, generated code, dynamic imports, framework magic, and runtime configuration may not resolve cleanly.
  • Noise: utility hubs can dominate. Narrow the corpus, query specific symbols, or tune clustering rather than forcing the whole monorepo into one map.
  • Privacy: code-only AST extraction is local, but semantic content—and code-derived community labels when remote naming is enabled—can reach the configured provider. Use --code-only, disable remote labeling, or select a local backend for sensitive work.
  • Repository weight: graphify-out/graph.json can be large. Decide as a team whether to commit it; ignore cost.json and optionally cache.
Measured evidence

Promising, not definitive

The project’s own ERPNext experiment reports key-fact coverage rising from 70.8% with grep/read to 82.0% when the same coding agent receives one Graphify tool (n=6 questions).

That is encouraging but small and maintainer-run. Treat “500× smarter” and similar community claims as marketing, not evidence.

My adoption gate

Keep it only if it changes decisions

Trial it on one medium/large repository for a week. Record five real questions. Keep Graphify if it finds dependencies you would have missed, reduces browsing time, or improves review scope. Drop it if you mostly ask exact-location questions.

06 · Practice lab

Learn it on your real repository in seven days.

Twenty minutes a day. No toy project required. Progress is stored only in this browser.

DAY 1Build

Install Graphify. Run a code-only extraction. Inspect all three outputs.

DAY 2Orient

Find entry points, god nodes, and communities. Verify three source locations.

DAY 3Trace

Pick one user request. Trace from boundary to storage or external API.

DAY 4Impact

Choose a service you know. Predict its blast radius, then check with LSP.

DAY 5Change

Give your coding agent a tiny task using graph → verify → edit → test.

DAY 6Review

Review a PR or recent commit. Look beyond changed lines into neighboring nodes.

DAY 7Decide

Update the graph. Compare value against maintenance and output size.

Final challenge: the no-guess refactor

Ask your agent to move one small responsibility across a module boundary. Require: Graphify impact map, source verification, explicit owned files, tests before and after, then a graph update. If the agent edits from the graph without reading source, stop it.
