Keyless web search and fetch for AI agents

The best hosted, genuinely no-account starting point is Tavily keyless: one documented REST integration for both search and URL extraction. The best published numerical allowance is Exa's unauthenticated MCP (150 calls/day, 3 requests/second), if your client speaks MCP. For maximum operational control, self-host SearXNG plus a separate extractor—but that is not an unlimited search index.

What “most generous” actually means

Quota certainty: Exa MCP publishes 150 anonymous calls/day and 3 requests/second for search and fetch; Tavily supports both operations without a key but publishes no numeric keyless quota. Ease of n8n integration: Tavily wins because it exposes ordinary JSON REST with a single opt-in header. Maximum control: SearXNG plus local extraction has no vendor account quota, but upstream engines can block it. There is no honest claim that any hosted keyless option offers unlimited use.[3][4][5][8][20]

Recommendation: prototype n8n with Tavily keyless /search and /extract. Use Exa hosted MCP as a second search/fetch path if your n8n version/client connects to its Streamable HTTP endpoint. For Pi, register two bounded tools in a small extension; call the same REST provider or bridge to Exa MCP. If sustained traffic is the goal, accept a free account/key or self-host rather than designing around anonymous quotas.[1][2][3][4][17][18]

Key distinction: Search finds candidate URLs and snippets; fetch resolves known URLs into page content. A search service does not necessarily fetch pages, and a reader is not necessarily a search engine.

Limits and risks by provider

Tavily — recommended hosted REST default

Official keyless mode requires X-Tavily-Access-Mode: keyless; POST /search and POST /extract work without an account. Its MCP endpoint requires the same header. No published numeric keyless cap means a workflow cannot promise a daily volume; failures can surface as natural-language limit instructions rather than your normal result schema, so inspect HTTP status and payload. An optional free account gives 1,000 credits/month, no card: basic search costs 1 credit, advanced search 2, and basic extraction costs 1 per five successful URLs. The keyed limit is not the anonymous limit.[3][10]

Exa — recommended when a known free daily budget matters

The official https://mcp.exa.ai/mcp exposes web_search_exa and web_fetch_exa without login. Exa documents 150 free unauthenticated calls/day and 3 QPS; its higher-level agent_run requires OAuth or an API key. The REST Search API is separately keyed. Risk: MCP adds protocol/session compatibility work to plain n8n HTTP flows; OAuth prompts in some client marketplaces are not evidence the direct keyless endpoint requires sign-in. Do not assume quota isolation per workflow or guaranteed SLA.[4][5][32]

Firecrawl Cloud — broad tools, opaque anonymous budget

Hosted keyless REST Search and Scrape are documented, and the keyless MCP specifically exposes Search, Scrape and Parse; Crawl/Map/Extract and batch scraping require a key. Anonymous usage hits both per-IP daily request and credit caps, with no published numbers. A free account provides 1,000 credits and a documented 10 requests/minute for search and scrape plus two concurrent browsers. Its search can optionally scrape results, which spends more credits. Risk: shared IPs, 429 responses, per-operation costs, timeouts, third-party page failures and changing cloud/open-source capability boundaries. The self-hosted stack includes core search/scrape/crawl/map but has more moving parts; its quickstart intentionally disables authentication and is unsafe to expose publicly.[6][12][9][21]

SearXNG — control without an independent index

GET /search?q=…&format=json is a documented API, but json must be enabled; otherwise it returns 403. Public instances often disable JSON or impose operator-specific limits, so do not build production automation on strangers' servers. Self-host privately and monitor engine health; Google/Bing/DDG upstreams may challenge or block the origin IP. SearXNG's own limiter is explicitly designed to curb traffic that gets upstream engines blocked. Add a separate fetch/extraction service; self-hosting removes a vendor account limit, not target-site restrictions or infrastructure cost.[8][20]

Reader and local fetchers — content, not search

Jina https://r.jina.ai/https://example.com is a remarkably simple no-key reader with a published 20 requests/minute anonymous limit. Jina also describes s.jina.ai search, but leaves the anonymous search column blank; the 100 requests/minute figure belongs to a free key. Do not treat it as a guaranteed keyless search quota. Local Trafilatura/Readability extract main content without a provider quota but need a fetch implementation; Crawl4AI adds browser-backed crawling and local serving, not a local general-web search index. In Crawl4AI, check_robots_txt defaults to false: turn it on deliberately. None bypass target-site terms, copyright, or access controls.[7][13][14][19][27]

Edge cases and exclusions

  • Brave: ordinary API needs a subscription key; the separate x402 agent endpoint is keyless but paid via a signed stablecoin payment per request. Read the live 402 price, enforce spend caps and avoid automatic wallet access by an untrusted agent.[11][23]
  • Marginalia: its deliberately shared public header is an interesting independent-web experiment, not an anonymous API or robust primary backend; the operator says it often rate-limits.[15]
  • DuckDuckGo HTML/Lite and Google/Bing SERP scraping: HTML user interfaces are not documented agent APIs. Forms and anti-bot behavior change; traffic can be challenged or violate usage restrictions. Do not mask scraping behind SearXNG and call it a quota guarantee.[20][25][33]
  • Brave's free credits, Tavily/Exa/Firecrawl keyed tiers, Serper and Mojeek: free or trial account is not no key. Google Custom Search JSON requires key and engine ID, is closed to new customers, and is scheduled to end January 2027; public Bing Search APIs were retired in 2025.[10][16][22][23]
  • Wikimedia and Common Crawl: useful keyless niche/historical corpora, not replacements for a general, fresh ranked web search. Wikimedia applies bot/API limits; Common Crawl indexes past crawls rather than the live web.[28][29]

How to wire n8n and Pi

n8n: simplest two-step REST workflow

Use an HTTP Request node with POST https://api.tavily.com/search, header X-Tavily-Access-Mode: keyless, JSON body {"query":"your query","max_results":5}. Retain only results[].url, title and snippets; select a small allowlisted set. Then POST https://api.tavily.com/extract with the same header and JSON {"urls":["https://example.com"]}. Cap results, time, concurrency and response length; cache by normalized query/URL, handle 429 with bounded backoff, and log only metadata. n8n's HTTP Request node supports JSON and can be attached as an AI Agent tool. For MCP, use n8n's MCP Client node for ordinary workflow steps or MCP Client Tool for an agent; confirm its installed version supports the remote endpoint transport, and configure Tavily's required header rather than assuming URL-only setup works.[2][3][17][18]

Pi: narrow tools, not a blind browser proxy

Create a trusted local TypeScript extension with pi.registerTool() for web_search(query, max_results) and web_fetch(url); enforce an HTTPS-only URL policy, DNS/IP re-checks against SSRF, redirect bounds, content-type and byte limits, timeouts and cancellation. Return URL/title/source and short bounded text, not raw HTML or executable instructions. Place it in a trusted extension location or load explicitly. Pi extensions run with the agent process's OS permissions; avoid installing arbitrary third-party search extensions unreviewed.[1]

Shared boundary: treat fetched pages as untrusted evidence, not instructions. Respect site access policies; exclude private networks and credentials from URL fetches, keep the instance private, and don't expose an open fetcher as a public webhook. Use a keyed plan when requirements include predictable throughput, observability, and support.

What was actually tested

On 3 October 2026, one live anonymous Tavily search and one extraction of https://example.com both returned HTTP 200 with expected result fields. Jina Reader returned HTTP 200 for that URL. The same host's keyless Firecrawl Search and Scrape calls both returned HTTP 429; this demonstrates that anonymous availability is not a reliable personal quota, but does not establish the global cap or reason for shared-IP exhaustion. Exa's endpoint was confirmed reachable but a plain HTTP GET returned 405; this is not an MCP tool-call test. No sustained load, benchmark, self-hosted deployment, n8n workflow execution, or Pi extension execution was performed. Pricing and limits are a documentation snapshot, not a service-level promise.
