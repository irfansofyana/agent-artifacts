⚠

GitLab support has one sharp edge

The full no-mistakes path can create and update GitLab MRs, inspect CI, fetch failed-job traces, and handle merge conflicts through glab. FirstMate can then watch and guard the merge. Its faster direct-PR template remains GitHub-only, and its universal bootstrap still requires authenticated gh plus GitHub-focused AXI tools.

02

Get one clean launch

Run this once on the machine where your repository credentials and coding agents live.

Check the hard prerequisites

Herdr 0.8.0 or newer enables the default one-task presentation spaces. FirstMate needs protocol 14 or newer and jq.

pi --version
herdr --version
herdr status --json | jq '{client: .client.version, protocol: .client.protocol, server: .server.status}'
herdr integration install pi
herdr integration status
git --version
jq --version
node --version
gh auth status
glab --version
glab auth status --hostname gitlab.example.com

Clone the distro into a dedicated home

Do not place FirstMate inside an office project. It keeps its own private registry, state, and project clones.

cd "$HOME"
git clone https://github.com/kunchenguid/firstmate.git firstmate-home
cd "$HOME/firstmate-home"
mkdir -p config
printf 'herdr\n' > config/backend
printf 'pi\n' > config/crew-harness

Launch Herdr, then Pi from the FirstMate checkout

Open Herdr, create or focus a terminal pane, enter the FirstMate directory, then run Pi. Approve Pi’s project trust prompt once for this clone.

herdr
cd "$HOME/firstmate-home"
pi

Avoid nesting tmux inside Herdr. FirstMate selects the innermost multiplexer, so a tmux pane inside Herdr routes workers to tmux.

03

The daily operating loop

Talk to FirstMate in outcomes. Let it handle worker panes, worktrees, task records, and supervision.

Start of day

Take bearings

  1. Open Herdr and return to the FirstMate workspace.
  2. Start or resume Pi from the FirstMate checkout.
  3. Ask /ahoy for unanswered events, or /bearings for fleet state.
  4. Resolve one decision before adding more work.
Dispatch

Write a task contract

  • Name the project and desired outcome.
  • State what stays out of scope.
  • Name acceptance checks and required tests.
  • Choose scout, direct-PR, or local-only.
Supervise

Watch state, not scrolling text

Herdr shows working, blocked, done, or idle. Ask FirstMate to inspect a worker when the state looks wrong. Routine work should not require you to type into worker panes.

Merge

Approve the exact MR

Require the full GitLab MR URL, passing pipeline at the current head, no conflicts, and resolved blocking discussions. Say “merge this MR” only after you review the result.

04

Prompts worth keeping

Copy, replace the bracketed values, and send them to the Pi session running FirstMate.

Small implementation

Ship one bounded change

In project [name], implement [outcome]. Keep [areas] out of scope. Acceptance: [checks]. Run [tests]. Use the project’s no-mistakes mode with yolo off. Use the supported GitLab provider path through glab. Return the full MR URL, risk level, tests run, and current CI state. Do not merge it.
Uncertain bug

Investigate, then ask

Scout project [name] for [symptom]. Reproduce it, identify the smallest likely fix, and write a report with evidence. Do not modify the project or open an MR. Ask me before promoting the scout into implementation.
Existing MR

Review without merging

Review this GitLab MR: [full MR URL]. Check correctness, security, regression risk, tests, and CI state. Do not push, comment, approve, or merge. Return findings ordered by severity with file and line evidence.
Parallel work

Split independent tasks

In project [name], run these independent tasks in parallel: (1) [task], (2) [task]. Use separate worktrees and separate GitLab MRs. Flag any file or behavior overlap before dispatch. Keep yolo off and do not merge either MR.
Steer

Change a worker’s instruction

For the worker handling [task], keep the current worktree and add this constraint: [constraint]. Confirm whether it changes scope, tests, or the MR plan.
Recovery

Recover without losing work

The worker for [task] looks stuck. Inspect its current state and recent output. Preserve its worktree and commits. Use FirstMate’s recovery ladder, report the cause, and relaunch only if the current process is dead or cannot continue.
05

Advanced controls

Add these after the basic loop works. Each feature creates more state to understand and recover.

Pi

Calm display

Use /calm to hide supported operational rows without changing model context or session data.

Cost

Cheaper supervision

Use /supervision-model to select a cheaper model and shallower effort for Pi’s supervision branch.

Focus

Quiet mode

Use /quiet while chatting and /quiet off to leave it. Use /afk when you step away.

Backend

One-shot Herdr

Launch with FM_BACKEND=herdr pi for one session. Keep config/backend for the standing choice.

Autonomy

Keep yolo off

Enable it only for low-risk, mature repositories. It grants standing merge authority for green in-scope work.

Scale

Add secondmates late

Use a persistent secondmate for a stable domain with enough ongoing work. One repo and short tasks do not need it.

Worker environment for self-managed GitLab

Workers inherit common executable paths. If your setup depends on extra environment names such as GITLAB_HOST, a proxy, or a custom CA path, add only the names you need to FirstMate’s launch allowlist. Prefer glab auth login with the OS keyring instead of token environment variables.

cd "$HOME/firstmate-home"
printf '%s\n' GITLAB_HOST HTTPS_PROXY SSL_CERT_FILE >> config/launch-env-allowlist
Versioning

Pin an audited commit

FirstMate has no releases or tags and its main branch changes fast. Mirror a reviewed commit to an internal default branch, or record the exact deployed SHA and review every update before using /updatefirstmate.

GitLab gaps

Know the provider limits

The GitLab no-mistakes path lacks GitHub’s unresolved review-bot comment ingestion and automatic rerun of transient cancelled or pre-run infrastructure checks. Fork MR routing is also unsupported.

06

Recover in this order

Preserve the worktree and task records. Ask FirstMate to apply these controls unless you are diagnosing the distro itself.

1 · StateAsk for current crew state
2 · PeekRead bounded recent output
3 · SteerSend one clear instruction
4 · InterruptStop the active turn
5 · RelaunchRestart the agent, keep work
Workers appear in tmux instead of Herdr
Run cat config/backend from the FirstMate checkout. It should contain herdr. Leave any nested tmux session before launching Pi because the innermost multiplexer wins.
Pi behaves like a normal coding agent
Start Pi from the FirstMate checkout and accept the project trust prompt. The tracked .pi/extensions files need that trust to load.
The worker tries to use gh-axi for a GitLab MR
The task entered FirstMate’s GitHub-only direct-PR path. Stop and re-dispatch through no-mistakes, whose provider adapter supports GitLab MR creation and CI through glab. Keep the existing worktree until FirstMate confirms the safe handoff.
FirstMate refuses to merge a GitLab MR with no pipeline
That refusal is expected. Its GitLab merge guard requires a successful pipeline attached to the current source-branch head, plus mergeable state, no conflicts, and resolved blocking discussions.
glab works in your shell but fails in a worker
Check that Herdr started under the same OS account, glab is on the pane’s PATH, and the target hostname is selected. Add required non-secret environment names to config/launch-env-allowlist. Do not paste tokens into prompts.
Herdr reports a client/server protocol mismatch
Run herdr status --json. Remove or upgrade an older binary shadowing the active client. Use herdr update --handoff when your environment supports it.
A worker terminal looks dead
Do not kill the pane or run a broad server stop. Ask FirstMate to inspect, interrupt, or relaunch the exact task. Raw pane cleanup can separate the terminal from its worktree and durable task state.
07

Office-safe defaults

Coding agents can read source, run commands, and reach authenticated developer tools. Treat their environment as privileged.

Credentials

Use the keyring

Authenticate with glab auth login. Never use glab auth status --show-token in an agent transcript. Grant only the scopes your GitLab workflow needs.

Authority

Keep human merge approval

Leave yolo off. Ask workers to open MRs, then review the exact URL, current pipeline, discussions, and diff before authorizing a merge.

Runtime

Treat Pi workers as autonomous

Pi has no permission system. Worktrees isolate Git checkouts, not OS credentials, network access, home-directory files, or processes. Pilot under a least-privilege account or approved disposable environment.

Cleanup

Use FirstMate’s lifecycle

Never force-remove a task with unlanded work. Let FirstMate verify the MR or approved local merge before it returns the worktree.

08

Prove it before office work

Use a disposable GitLab repository with real CI and branch protections. One green demo is weaker than a controlled refusal test.

Rollout: local-only smoke test → disposable GitLab no-mistakes project → one attended low-risk repository → parallel independent tasks → cost tuning → away mode or secondmates.
