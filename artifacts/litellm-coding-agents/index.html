Before you connect

Do these three things once. Everything below assumes the gateway already exposes the model aliases you intend to use.

1 · Pick the wire API

Claude uses Anthropic Messages. Codex requires Responses. Pi and OpenCode can use Responses or Chat Completions.

2 · Curate aliases in LiteLLM

Expose stable names such as gpt-5.6-sol, gpt-5.6-terra, and claude-opus-4-7.

3 · Protect the key

Provide LITELLM_API_KEY through a managed environment or OS secret helper. Never commit it to a project file.

Pick your agent

Each panel is complete enough to use on its own.

Pi

Explicit model list, hot-reloaded from one JSON file.

Responses API
01

Create ~/.pi/agent/models.json

Pi does not need dynamic discovery here; define exactly the models you want available.

models.json
{
  "providers": {
    "litellm": {
      "baseUrl": "https://litellm.company.com/v1",
      "api": "openai-responses",
      "apiKey": "$LITELLM_API_KEY",
      "models": [
        { "id": "gpt-5.6-sol", "name": "Sol via LiteLLM", "reasoning": true },
        { "id": "gpt-5.6-terra", "name": "Terra via LiteLLM", "reasoning": true },
        { "id": "gpt-5.6-luna", "name": "Luna via LiteLLM", "reasoning": true }
      ]
    }
  }
}
02

Select and verify

Open /model, choose litellm/<model-id>, then send a small tool-using task. Pi reloads the file whenever you open the picker.

Fallback: if a deployment does not support Responses, change api to openai-completions.

Claude Code Desktop

The Desktop Code tab and CLI share Claude Code settings.

Anthropic Messages
01

Set gateway environment in ~/.claude/settings.json

settings.json
{
  "env": {
    "ANTHROPIC_BASE_URL": "https://litellm.company.com",
    "CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY": "1"
  },
  "apiKeyHelper": "/absolute/path/to/your-litellm-key-helper"
}
Secret handling: the helper should return the key from your OS or company secret store. Do not place the key itself in this file.
02

Open the Code tab and pick a model

Start a new local session and use the dropdown next to Send. Claude Code 2.1.129+ can load models from the gateway’s /v1/models.

Discovery filter: only IDs beginning with claude or anthropic are added. If your alias does not match, set the default Claude model variables or add one custom picker option.
03

Verify

Use /status to confirm the resolved base URL and provider, then run a small edit. Gateway models are cached and refreshed at startup.

Codex Desktop

Routing works. Custom-provider model-list UX is the sharp edge.

Responses API only
01

Configure ~/.codex/config.toml

Desktop, CLI, and the IDE extension share this user-level file.

config.toml
model = "gpt-5.6-terra"
model_provider = "litellm"
model_reasoning_effort = "medium"

[model_providers.litellm]
name = "LiteLLM"
base_url = "https://litellm.company.com/v1"
env_key = "LITELLM_API_KEY"
wire_api = "responses"
requires_openai_auth = false
supports_websockets = false
02

Understand the model list

LiteLLM exposes standard OpenAI model data. Codex currently expects richer internal model metadata, so Desktop does not reliably turn LiteLLM’s /v1/models into a usable custom picker.

MethodDesktop resultRecommendation
model = "…"Routes new sessions to that aliasUse this
Standard /v1/modelsNot a reliable custom list sourceDo not depend on it
model_catalog_jsonCan replace the catalog, but schema and Desktop behavior are fragileAvoid for routine setup
CLI /model or -mEasy per-session override in CLIBest for frequent switching
Bottom line: for Codex Desktop + LiteLLM, treat model as the selected alias. Change it, restart Desktop, and create a new chat. Existing chats may retain their original model.
03

Pick among three LiteLLM aliases

gpt-5.6-solHard, ambiguous, high-value work
gpt-5.6-terraPragmatic default for daily coding
gpt-5.6-lunaFast, clear, repeatable tasks

Set model_reasoning_effort to a level the selected upstream model supports. xhigh is model-dependent.

OpenCode

Define the provider and its visible models together.

Responses API
01

Add a custom provider to opencode.json

opencode.json · current v1 format
{
  "$schema": "https://opencode.ai/config.json",
  "model": "litellm/gpt-5.6-terra",
  "provider": {
    "litellm": {
      "npm": "@ai-sdk/openai",
      "name": "LiteLLM",
      "options": {
        "baseURL": "https://litellm.company.com/v1",
        "apiKey": "{env:LITELLM_API_KEY}"
      },
      "models": {
        "gpt-5.6-sol": { "name": "Sol via LiteLLM" },
        "gpt-5.6-terra": { "name": "Terra via LiteLLM" },
        "gpt-5.6-luna": { "name": "Luna via LiteLLM" }
      }
    }
  }
}
02

Select and verify

Run /models; the three configured models should appear under LiteLLM. Use litellm/model-id as the full ID.

Fallback: for Chat Completions-only deployments, use @ai-sdk/openai-compatible instead.
