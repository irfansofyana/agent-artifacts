Git worktrees × AI coding agents

Parallel work.
Without collisions.

A copy-ready operating guide for running Pi, Codex CLI, and Claude Code on multiple tasks in one repository—each isolated, reviewable, and easy to remove.

Verified 19 July 2026
Against local CLI help for Pi 0.80.10, Codex CLI 0.144.1, Claude Code 2.1.207, plus first-party Git and vendor documentation.
The whole model

One task → one branch → one worktree → one agent session.

01 / Mental model

Share Git history. Isolate files.

A worktree is another checkout of the same repository. Every worktree has its own working files, index, branch, and agent context—but shares objects, refs, remotes, and repository history.

Coordinator

Main checkout

Read, review, fetch, inspect PRs. Keep it boring and preferably clean.

~/src/acme
→
Pi

Auth worktree

Branch ai/auth. Pi owns only auth scope.

~/src/acme-wt/auth
+
Codex / Claude

Other worktrees

Branches ai/api and ai/ui. Independent files, tests, commits.

~/src/acme-wt/{api,ui}
Do

Give every task a distinct branch and directory. Name the agent session after the task.

Do not

Run two write-capable agents in the same checkout. They will overwrite context and edits.

Parallelize

Tasks with disjoint ownership: UI, API endpoint, tests, docs, separate services.

Serialize

Two tasks that rewrite the same core file, schema, lockfile, or migration chain.

02 / Manual setup

Create sibling worktrees from a known base.

Sibling directories keep agent checkouts out of your main repository’s untracked-file view. Branch from origin/main when tasks should start clean and independently.

Run from the main checkout
# Confirm where you are and inspect current state
git rev-parse --show-toplevel
git status --short
git fetch origin

# Choose a sibling worktree home
ROOT="$(git rev-parse --show-toplevel)"
PROJECT="$(basename "$ROOT")"
WT_HOME="$(dirname "$ROOT")/${PROJECT}-worktrees"
mkdir -p "$WT_HOME"

# One branch + directory per task
git worktree add -b ai/auth "$WT_HOME/auth" origin/main
git worktree add -b ai/api  "$WT_HOME/api"  origin/main
git worktree add -b ai/ui   "$WT_HOME/ui"   origin/main

git worktree list
Branch rule: Git will not let the same local branch be checked out in two worktrees. That is protection, not inconvenience. Create a separate branch even when two agents are trying alternative implementations.

Command generator

Generate one worktree command. Paths are shell-quoted; nothing is executed here.

Generated command

      


      
Initialize each fresh checkout

      
Example: Node project
cd "$WT_HOME/auth"
npm ci                 # or pnpm install --frozen-lockfile
npm test -- --runInBand # establish a clean baseline before edits

      
Tracked files appear automatically. Gitignored files do not. Copy only the exact local config the task needs; never give every agent your whole secrets directory. Claude Code’s native worktrees support a project-level .worktreeinclude for explicitly selected gitignored files.

Same isolation. Different launch ergonomics.
Pi and Codex CLI use worktrees you create with Git. Claude Code can use those too, or create its own with --worktree.

04 / Task contract
Give boundaries, not vibes.
Parallel agents fail less from Git than from ambiguous ownership. Every launch prompt should define scope, acceptance, validation, and forbidden actions.

      
Reusable prompt
Paste this into Pi, Codex, or Claude. Replace the bracketed fields.
TASK: [one concrete outcome]

OWNERSHIP
- You own: [directories/files/components]
- Do not modify: [shared or agent-owned areas]
- Base branch: [origin/main or dependency branch]

ACCEPTANCE
- [observable behavior 1]
- [observable behavior 2]
- No unrelated refactors or dependency upgrades

VALIDATION
- Run: [focused test command]
- Run: [lint/typecheck command]
- Report exact commands and results

GIT / SAFETY
- Stay inside the current worktree
- Never push, merge, rebase, force-push, or delete branches
- Do not rewrite tests merely to make them pass
- Stop and report if the task requires an out-of-scope shared-file change

FINISH
- Summarize changed files, tests, assumptions, and remaining risk
- Leave changes ready for human review

    


    

      
05 / Worked example
Three tasks. Three tools. One repository.
Pi handles auth, Codex builds an API endpoint, and Claude builds UI. The main checkout coordinates; no agent touches another agent’s files.

      
1. Create all worktrees
git fetch origin
git worktree add -b ai/auth-passkeys ../acme-wt-auth origin/main
git worktree add -b ai/export-api    ../acme-wt-api  origin/main
git worktree add -b ai/settings-ui   ../acme-wt-ui   origin/main

      
2. Launch in three terminals
# Terminal A — Pi
cd ../acme-wt-auth && pi --name auth-passkeys "Implement passkey enrollment per the task contract."

# Terminal B — Codex
codex exec -C ../acme-wt-api --sandbox workspace-write \
  "Add customer export API per the task contract. Run focused tests."

# Terminal C — Claude Code
cd ../acme-wt-ui && claude --name settings-ui \
  "Build the settings UI per the task contract. Run focused tests."

      

        
Monitor without entering
Coordinator commands
git worktree list --porcelain
git -C ../acme-wt-auth status --short
git -C ../acme-wt-api diff --stat
git -C ../acme-wt-ui log -3 --oneline

        
Keep runtime state separate
  • Assign ports: UI 3101, API 8102, auth test server 8103.
  • Use separate test databases or schemas.
  • Do not run competing migration writers.
  • Expect duplicate dependency directories; share package caches, not node_modules.
  • Keep generated files and local config gitignored.

      

    


    

      
06 / Review & integrate
Agents produce branches. You decide what lands.
Review each worktree independently. Prefer one PR per task. Merge the lowest-level dependency first, then update dependent branches from the new main.

      
Inspect
Status, diff, generated files, dependency changes.
Test
Run focused tests, then the relevant integration suite.
Commit
Stage intentionally. One task-shaped commit or small series.
Push + PR
Never push from the coordinator’s main branch.
Merge + rebase
Merge independent PRs; refresh dependent worktrees.

      
Review, commit, push, open PR
# Review from anywhere
git -C ../acme-wt-auth status --short
git -C ../acme-wt-auth diff

# Run the real project checks inside that worktree
git -C ../acme-wt-auth diff --check
cd ../acme-wt-auth && npm test

# Stage deliberately; inspect staged diff before commit
git -C ../acme-wt-auth add -p
git -C ../acme-wt-auth diff --cached
git -C ../acme-wt-auth commit -m "feat(auth): add passkey enrollment"

git -C ../acme-wt-auth push -u origin ai/auth-passkeys
gh pr create --head ai/auth-passkeys --base main \
  --title "feat(auth): add passkey enrollment" \
  --body "Implements passkey enrollment with focused tests."

      
Integration order: if the UI depends on a new API contract, merge the API first. Then run git -C ../acme-wt-ui fetch origin and git -C ../acme-wt-ui rebase origin/main. Resolve conflicts in the affected worktree, with one human or agent owning the resolution—not three agents racing.

      
Do not merge worktrees into one another by copying files. Use commits, PRs, rebases, merges, or cherry-picks. Copy/paste destroys provenance and makes conflict handling worse.

    


    

      
07 / Safe cleanup
Remove the checkout only after the work is durable.
A normal worktree removal refuses dirty state. That friction protects you. Confirm the branch is pushed or merged before deleting anything.

      
Cleanup sequence
# 1. Inspect before removal
git -C ../acme-wt-auth status --short
git -C ../acme-wt-auth log --oneline origin/main..HEAD

# 2. Remove checkout (refuses unsafe dirty removal)
git worktree remove ../acme-wt-auth

# 3. Delete local branch only after merge
git branch -d ai/auth-passkeys

# 4. Inspect stale metadata before pruning
git worktree prune --dry-run
git worktree prune
git worktree list

      
Avoid git worktree remove --force. It can discard uncommitted files. If a worktree directory disappeared manually, committed work still exists on its branch; recreate it with git worktree add ../recovery ai/auth-passkeys.

    


    

      
08 / Failure modes
The collisions Git cannot prevent.
Worktrees isolate files. They do not isolate architecture, remote branches, databases, ports, package registries, cloud resources, or your attention.

      
Two agents need the same shared file
Do not pretend this is parallel. Extract and merge the shared contract first, then branch the dependent tasks from that commit. Alternatively give one agent ownership and make the second wait.

      
Both agents modify the lockfile
Prefer merging the dependency-changing task first. Rebase the other branch and regenerate the lockfile with the canonical package manager; do not hand-merge lockfile conflict markers.

      
Local services fight over ports or databases
Assign per-worktree ports and database names through local environment files. For destructive migrations, run only one migration-owning task at a time.

      
An agent pushes or rebases unexpectedly
Prompts are not security boundaries. Use tool permissions/sandboxing, branch protection, least-privilege tokens, and review gates. Tell agents not to push, but also configure credentials so a mistaken push cannot bypass protected branches.

      
The main checkout is dirty
You can still create worktrees from origin/main, but the coordinator becomes harder to reason about. Commit, stash, or move the unrelated work to its own worktree before orchestrating parallel agents.

      
The worktree has no .env or dependencies
That is normal: it is a fresh checkout. Install dependencies per worktree and provision only the minimum local config. Claude Code can copy explicitly listed, gitignored files via .worktreeinclude; manual Git worktrees need your own setup step.

Commands worth remembering.

      
IntentCommandNotes

        
Create new taskgit worktree add -b ai/task ../repo-wt-task origin/mainNew branch from clean remote base.

        
Use existing branchgit worktree add ../repo-wt-task ai/taskBranch cannot already be checked out elsewhere.

        
Listgit worktree list --porcelainMachine-friendly paths, branches, lock state.
