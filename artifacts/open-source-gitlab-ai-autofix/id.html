Proyek open-source yang pakai AI untuk memperbaiki kerentanan GitLab

Jawaban singkatnya: belum ada proyek open-source yang sekaligus banyak dipakai dan dibangun untuk memperbaiki temuan GitLab pakai AI. Pemberi fix AI dengan bintang terbanyak umumnya generik atau berpusat di GitHub. Yang khusus GitLab masih baru dan adopsinya belum banyak.

Kesimpulan

Kalau butuh alur fix GitLab sekarang, pakai Semgrep untuk temuan dan saran perbaikannya, plus agentic resolution dari GitLab Duo kalau kamu di tier Ultimate. Keduanya dipercaya banyak tim. Tapi dua-duanya bukan pipeline AI fix yang sepenuhnya open.

Kalau butuh alur AI fix yang open dan self-hosted, belum ada proyek di bawah yang aman dijadikan default. SecureFix paling cocok untuk GitLab, tapi belum punya lisensi dan belum ada adopsinya. OpenHands punya adopsi, tapi vulnerability-fixer-nya prototipe yang hanya untuk GitHub.

Bintang mengukur perhatian, bukan apakah fix-nya benar. Saya tidak menjalankan satu pun tool ini terhadap proyek GitLab. Anggap ini shortlist untuk diuji, bukan vonis soal kualitas.

Kalau syaratnya draft MR dari CI, Codex Security yang dokumentasinya menjelaskan job itu. Pixee dan Aikido juga membuka MR GitLab, dari layanan mereka sendiri, bukan dari template yang di-import.

Keputusan, 19 November 2026

Tujuannya fixer yang gampang diadopsi tim lain, berbentuk job CI, dan berhenti di draft merge request.

Bisa, di job yang kita tulis sendiri. codex-security scan --patch --create-pr bisa scan, patch, lalu buka draft MR. Pipeline GitLab resmi tidak bisa melakukan itu tanpa OpenAI key yang sudah punya akses Codex Security.

Tanpa program itu, CLI tetap menerima OpenRouter, Fireworks, dan Bedrock. LiteLLM bukan nilai --provider. Arahkan CLI ke sana lewat override Codex, dan alias-nya harus mencantumkan /v1/responses di supported_endpoints. Route yang dijembatani membuang field yang dibutuhkan scan.

MR hanya terbuka untuk patch yang verified. Push-nya lokal: glab plus project token dengan scope api dan write_repository. CI_JOB_TOKEN tidak bisa membuat MR. Model Daybreak tetap di belakang Trusted Access, jadi sebagian kelas temuan bisa ditolak model di belakang gateway. Kombinasi ini belum dijalankan.

Tabel open-source tetap tidak punya proyek yang banyak dipakai untuk loop ini. Catatan Codex Security ada di https://artifacts.irfansp.dev/codex-security-gitlab/.

Fitur vendor (bukan open source)

  • GitLab Duo Agentic SAST Vulnerability Resolution. Generally available since GitLab 18.11. Opens an MR with a fix for High and Critical SAST findings on the default branch. Needs GitLab Ultimate, GitLab Duo Agent Platform, and the flows turned on.
  • GitLab Duo Vulnerability Resolution (non-agentic). Creates an MR suggestion comment on a SAST finding. Ultimate tier, default model Anthropic Claude Sonnet 4.6, and the output needs review.

Membuka merge request

Tabel open-source tidak punya tool yang banyak dipakai dan membuka MR fix GitLab dari CI. Component GitLab Shannon yang open-source tidak mencakup remediation. Fix pull request ada di Shannon berbayar, dan dokumentasinya tidak bilang MR-nya mendarat di GitLab.

Dari tool di bawah, hanya Codex Security yang mendokumentasikan jalurnya sebagai job GitLab CI, dan job itu YAML yang ditempel, bukan CI/CD Catalog component. Pixee dan Aikido membuka MR dari platform mereka. Alur agentic GitLab Duo, di daftar vendor di atas, juga membuka MR di tier Ultimate.

  • Codex Security. OpenAI, masih research preview. Contoh GitLab CI resminya membuka draft MR kalau CODEX_SECURITY_CREATE_MR true, di branch codex-security/fix-<finding-hash>, dan tidak pernah merge. YAML-nya ditempel, bukan include. Butuh OpenAI key yang punya akses Codex Security. Ingest SARIF butuh GitLab Ultimate 19.2 atau lebih baru. Contohnya mem-pin CLI di 0.8.1.
  • Pixee. Komersial. Membuka merge request GitLab untuk temuan SAST dan dependency lewat token service-account dan webhook. Dokumentasinya bilang .gitlab-ci.yml tidak perlu diubah. Jalan di GitLab.com dan GitLab self-hosted. Bukan template CI yang bisa di-import.
  • Aikido AutoFix. Komersial. Membuka merge request GitLab, dan ada setting untuk menandainya sebagai draft. Konfigurasinya UI Aikido plus file .aikido opsional, bukan CI include.

Cara pengecekannya

Jumlah bintang, lisensi, tanggal push terakhir, dan deskripsi diambil dari GitHub REST API pada 18 November 2026. README dibaca dari raw.githubusercontent.com. Klaim dukungan GitLab berasal dari teks README dan dokumentasi GitLab, bukan dari menjalankan tool-nya.

Belum dijalankan di riset ini: apakah Strix atau Shannon benar-benar membuka MR fix di GitLab. Dokumentasi Renovate bilang dia membuat merge request di GitLab; Renovate tidak dijalankan di sini. Lisensi VulnHunter Apache-2.0, dibaca dari file LICENSE di repo.

Jumlah bintang berubah setiap hari. Cek ulang sebelum memutuskan.
