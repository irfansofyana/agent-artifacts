3 sample deployable yang layak di-clone

aws-samples/sample-OpenClaw-on-AWS-with-Bedrock

AWS sampleMIT-0418★

Satu stack CloudFormation yang menaikkan OpenClaw di instance Graviton, pakai Bedrock untuk akses model, SSM Session Manager sebagai ganti SSH terbuka, VPC endpoints, dan CloudTrail. README-nya bilang deploy sekitar 8 menit dan mulai dari sekitar $30/bulan. Plugin messaging sudah terpasang. Tombol launch-nya mencakup us-west-2, us-east-1, eu-west-1, dan ap-northeast-1.

  • Akses model Bedrock diurus stack-nya, jadi tidak ada API key di instance.
  • Aksesnya lewat SSM, jadi tanpa inbound port dan tanpa SSH key.
  • Catatan: template sekali klik-nya ada di satu bucket S3, jadi untuk region lain kamu harus upload template-nya sendiri.

aws-samples/sample-host-hermesagent-on-amazon-bedrock-agentcore

AWS sampleMIT-045★

Opsi paling menarik secara arsitektur untuk Hermes: Firecracker microVM per user di AgentCore Runtime, 9 stack CDK, API Gateway plus Lambda router untuk webhook masuk, dan gateway ECS Fargate untuk channel yang butuh koneksi panjang. State-nya di S3, jadi memory dan session tetap hidup meski microVM-nya mati.

  • Integrasinya berupa monkey-patch yang menukar anthropic.Anthropic dengan anthropic.AnthropicBedrock, jadi semua inference lewat Bedrock dengan SigV4 dan IAM, sementara source Hermes di upstream tidak diubah.
  • Channel: Telegram, Slack, Discord, dan Feishu via webhook; WeChat lewat gateway Fargate.
  • Catatan: terikat region, lihat bagian Jakarta.

JiaDe-Wu/sample-hermes-agent-on-aws-with-bedrock

MIT19★

Sample yang ditautkan langsung oleh dokumentasi Hermes: CloudFormation bikin VPC, IAM role, instance EC2, dan konfigurasi Bedrock dalam satu klik. Kerja provider Bedrock native-nya sudah di-merge ke upstream, jadi deploy-nya install dari rilis PyPI resmi, bukan fork. Jalur terpendek dari nol ke Hermes yang jalan di EC2.

Ada juga aws-samples/sample-hermes-agents-on-agentcore, lebih baru dan lebih tipis, berguna kalau kamu mau lebih dari satu Hermes agent di akun AgentCore yang sama.

Dua-duanya bicara Bedrock secara native

Ini yang bikin seluruh cerita AWS-nya masuk: API key hilang dari gambaran. Auth-nya pakai AWS SDK credential chain, jadi cukup IAM role di instance.

OpenClaw punya provider Bedrock Converse streaming, plus provider terpisah Bedrock Mantle untuk endpoint yang kompatibel OpenAI dan melayani model terbuka.

# OpenClaw: provider metadata
# provider: amazon-bedrock
# api:      bedrock-converse-stream
# auth:     aws-sdk  (env vars, shared config, or instance role)

# On EC2 the instance role is invisible to env-marker detection,
# so discovery has to be turned on explicitly:
openclaw config set plugins.entries.amazon-bedrock.config.discovery.enabled true
openclaw config set plugins.entries.amazon-bedrock.config.discovery.region ap-southeast-3
openclaw models list

Discovery memanggil bedrock:ListFoundationModels dan bedrock:ListInferenceProfiles, lalu cache satu jam. Model ID polos hanya muncul kalau Bedrock melaporkan dukungan on-demand; model yang cuma lewat inference profile akan tampil sebagai profile us. atau global., karena profile-profile itu punya perilaku data residency yang berbeda. Model tersembunyi tetap bisa ditambah manual di models.providers["amazon-bedrock"].models.

Hermes Agent mengarahkan tiap keluarga model lewat API yang paling cocok, bukan memaksa semuanya lewat satu jalur.

# Hermes Agent: Bedrock provider
cd ~/.hermes/hermes-agent && python -c "import pm; pm.sync_venv(['bedrock'], explicit=True)"
hermes model        # More providers... -> AWS Bedrock -> region -> model

# config.yaml afterwards
# model:
#   default: us.anthropic.claude-sonnet-4-6
#   provider: bedrock
# bedrock:
#   region: ap-southeast-3

Cek kenyataan Jakarta

ap-southeast-3 mencakup EC2 dan Lightsail, bukan AgentCore

Dicek ke data ketersediaan region AWS pada 18 November 2026: Amazon Bedrock dan Amazon Lightsail keduanya berstatus tersedia di ap-southeast-3. Amazon Bedrock AgentCore berstatus direncanakan, belum tersedia.

Jadi jalur EC2 dan Lightsail bisa jalan di Jakarta hari ini, dengan Bedrock sebagai backend modelnya. Sample Hermes berbasis AgentCore perlu region tetangga sampai AgentCore masuk, dan itu keputusan cross-region data processing yang harus dipilih sadar, bukan default.

Satu detail lain soal Jakarta: tombol launch CloudFormation di kedua repo aws-samples menunjuk region tetap dan satu bucket template. Untuk ap-southeast-3 kamu perlu host ulang template-nya di bucket sendiri, launch dari sana, dan cek model mana yang benar-benar tersedia in-region sebelum menentukan model default.

Yang sebenarnya akan aku lakukan

  1. Jakarta, EC2, Bedrock. Jalankan instance Graviton dari sample CloudFormation aws-samples, di-host ulang untuk ap-southeast-3. IAM role untuk Bedrock, akses lewat SSM, tanpa inbound port. Jalur terpendek yang memenuhi batasan Jakarta-only hari ini.
  2. Simpan sample AgentCore dulu. Arsitekturnya lebih baik untuk isolasi per user jangka panjang, tapi belum bisa deploy di Jakarta, dan memindahkan stack CDK ke region tetangga itu keputusan data residency, bukan sekadar ganti config.
  3. Lewati EKS kecuali multi-tenancy memang kebutuhan. Satu agent per orang di instance sendiri lebih murah dan lebih gampang dipikirkan daripada cluster dengan cell per user, dan panduan keamanan OpenClaw sendiri bilang gateway bersama bukan batas kepercayaan.
  4. Pakai modul Terraform hanya untuk sisi AWS-native-nya. infrahouse/terraform-aws-openclaw layak dibaca untuk pola ALB plus Cognito, tapi gateway pribadi di belakang SSM tidak butuh ALB.
