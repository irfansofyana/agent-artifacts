OpenClawComplete native loop

Streams one final message, drives Agent Session status, handles Slack's native Stop event, and routes the click through the same cancellation path as /stop.

HermesOne event short

Streams well and cancels through /stop or !stop. Its inspected manifest and adapter omit agent_session_stopped, so Slack cannot show a working native Stop control.

Plan compatibility

Core agent messaging works on Free; the dedicated shell is the fuzzy boundary

Slack's streaming and Agent Session primitives are usable in ordinary Free-workspace threads. The plan ambiguity sits around the dedicated Agent app container and adjacent product surfaces, not the core response loop.

Slack Free

Native agent messaging in threads

  • Receive mentions, DMs, and thread replies
  • Stream responses with chat.startStream, chat.appendStream, and chat.stopStream
  • Drive processing and active Agent Session states
  • Show Slack's native Stop control and handle agent_session_stopped
  • Fall back to a placeholder plus rate-aware chat.update
  • Render Block Kit, buttons, approvals, and tables
  • Offer custom Stop through a button, /stop, or !stop
  • Use Events API or Socket Mode

Trade-off: Free-workspace retention, message, and usage limits still apply. Do not promise every discovery, sidebar, or split-view surface.

Any paid Slack plan

Safest target for the complete shell

  • Everything in the Free-compatible fallback
  • Dedicated Agent app container and conversation surface
  • Discovery, sidebar, and split-view experiences
  • A clearer support contract for Marketplace distribution

Build target: Pro, Business+, and Enterprise. A fully featured Developer Program sandbox is the free development path.

Six Slack operations create the agent experience

Slack splits the experience across message streaming, session lifecycle, and cancellation. Your backend must connect them to one run keyed by workspace, channel, and thread.

chat.stopStream does not cancel your model or tools. Slack stops the visible stream. Your handler must abort the run, clean up resources, discard buffered output, and move the Agent Session away from processing. Slack documents that responsibility explicitly.

Reference implementation

OpenClaw treats Stop as a control-plane event

1 · Slack emits the stop intent

The app subscribes to agent_session_stopped. Slack includes the actor, channel, thread root, and timestamps of streams it halted.

2 · OpenClaw authorizes and resolves ownership

The handler maps the visible Slack thread to current run owners. It keeps workspace identity attached so Enterprise Grid and Slack Connect cannot cross wires.

3 · The handler dispatches canonical /stop

Typed and clicked Stop share authorization, queue cleanup, agent abort, and subagent cancellation. One cancellation function prevents behavior drift.

4 · Delivery bookkeeping blocks late output

OpenClaw marks Slack-halted stream timestamps before abort cleanup. Buffered tails cannot leak into a message after the user pressed Stop.

Primary source: OpenClaw Stop event handler, Agent Session status implementation, and stream lifecycle and halted-stream bookkeeping.

Hermes snapshot

Hermes already has the cancellation engine; Slack cannot invoke it by click

Hermes streams deltas into one Slack message and seals it with chat.stopStream. It can render plan/task chunks, switch to chat.postMessage plus chat.update, and cancel a busy run through /stop.

The missing bridge is small in surface area and serious in behavior: add the event to the manifest, register a handler, authorize the user, resolve the thread's active run, invoke the existing stop path, and settle session state.

Missing in inspected commit bot_events: - agent_session_stopped @app.event("agent_session_stopped") async def stop_session(...): await canonical_stop(...)

Manifest gap: Hermes also omits reactions:write while its lifecycle code calls reactions.add and reactions.remove.

Migration gap: the modern agents.sessions.setStatus API accepts lifecycle enums, not custom strings such as is thinking....

Rendering

Use three render paths, because Slack has three text models

Stream body

Standard Markdown

chat.*Stream accepts markdown_text. Append deltas only. The field caps each call's Markdown payload at 12,000 characters.

Ordinary message

Slack mrkdwn

Convert authored Markdown. Slack uses *bold*, _italic_, ~strike~, and <url|label>. Escape untrusted angle tokens and preserve code fences.

Structure and controls

Blocks and chunks

Use Block Kit for buttons, approvals, tables, and durable layouts. Use plan_update and task_update inside streams. Include plain fallback text for notifications and assistive technology.

Useful limits: 50 Block Kit blocks per message; 3,000 characters per standard text object; 100 rows, 20 columns, and 10,000 aggregate cell characters for one table block. Treat limits as renderer inputs, not production surprises.
Recommended build

One cancellation function, two ways to invoke it

  1. Key runs by (team_id, channel_id, thread_ts).Store the runtime handle, cancellation token, stream timestamps, and session generation under that key.
  2. Open the lifecycle before output.Set processing, then start one append-only stream. Coalesce routine progress to protect rate limits.
  3. Route native Stop and /stop together.Authorize the actor, mark the generation cancelled, abort model/tools/subagents, clear queued work, and reject later output.
  4. Settle visibility after runtime cancellation.Record Slack-halted stream timestamps, finalize only when safe, send one confirmation, then set active or closed.
  5. Make the handler idempotent.Slack can retry events. A repeated Stop must not resurrect work, duplicate confirmations, or append stale buffers.
