One task.Seven prompt dialects.

Frontier models share the same grammar: objective, context, constraints, output contract. Each model places a different tax on vague scope, excessive scaffolding, weak evidence rules, or the wrong reasoning effort. This guide shows where to tune.

The operating rule

Write a task contract, then tune the dialect.

Model-specific tricks cannot rescue a fuzzy request. Give the model enough information to make the same trade-offs you would make, and tell it how you will judge the result.

Task

One outcome, stated as an action.

Context

Facts that change the answer.

Contract

Audience, format, scope, boundaries.

Check

Tests or evidence the result must satisfy.

Failure patterns
Six ways to waste a frontier model.

        

          
Failure 01
Persona without a job
“You are a world-class expert” adds little. Give domain facts, an outcome, and a quality bar.

          
Failure 02
Manual chain-of-thought scripts
Modern reasoning models plan better with a goal and evaluation criteria than a guessed reasoning recipe.

          
Failure 03
Repeated rules
Repetition can distort priority and trigger defensive behavior. State each rule once.

          
Failure 04
Maximum effort by default
High effort raises latency and can produce excess exploration. Earn it with task difficulty.

          
Failure 05
Long context as a junk drawer
Large windows still lose signal. Remove stale material and put the live question where the model expects it.

          
Failure 06
Benchmark worship
A leaderboard measures one harness and rubric. Build a small eval set from your recurring work.
